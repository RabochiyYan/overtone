ОКНО ОВЕРТОНА — ПУТЕВОДИТЕЛЬ ПО КОДУ

Этот гайд описывает текущую версию: 54 канала, 9 сообществ по 6 узлов, таймер первой фазы и параллельную анимацию связей одного источника.
Все пути ниже указаны относительно папки проекта overtone.

1. КАК РАБОТАТЬ БЕЗ ЛИШНЕГО РИСКА

1) Останови Play перед изменениями.
2) Скопируй Assets/Overtone и Assets/Scenes/OvertonePrototype.unity вместе с .meta-файлами или сохрани изменения в Git.
3) Меняй одну вещь за раз. Сохрани файл, вернись в Unity и дождись компиляции.
4) При ошибке сначала исправляй первую красную запись Console: последующие часто вызваны ею.
5) Открой Assets/Scenes/OvertonePrototype.unity и нажми Play.

Не редактируй Library, PackageCache и сгенерированные файлы сборки. Не удаляй .meta вручную: Unity хранит в них идентификаторы ресурсов.

ВАЖНО: интерфейс создаётся кодом во время игры. Если передвинуть кружок или кнопку в Hierarchy во время Play, следующая перерисовка затрёт это изменение. Для постоянного результата меняй данные или GameView.cs.

2. ЧТО МОЖНО МЕНЯТЬ БЕЗ ПРОГРАММИРОВАНИЯ

В Project выбери Assets/Overtone/PrototypeSettings.asset. Его поля откроются в Inspector.

Поле                       Значение сейчас      Что меняет
folderTarget               12                   Сколько реальных новостей собрать
startingLives              3                    Число допусков
sortingSeconds             30                   Лимит всей первой фазы
waveDelay                  0.65                 Задержку между волнами распространения
checkDuration              0.4                  Длительность одновременной проверки связей одного узла
crossClusterMultiplier     0.85                 Вероятность перехода между сообществами: меньше — сложнее
viewTargets                50000…95000          Цель просмотров каждого раунда

Не делай viewTargets пустым. Сейчас нужно 10 значений. Если значений меньше числа раундов, для оставшихся раундов повторяется последнее.

Разница между .cs и .asset:
PrototypeSettings.cs объявляет поля и значения по умолчанию для НОВОГО ресурса. Уже существующий PrototypeSettings.asset хранит свои значения. Например, изменение «sortingSeconds = 60f» в .cs само по себе не обновит существующий .asset: меняй число в Inspector.

У объекта GameSession в сцене поле settings должно ссылаться на этот .asset.

3. КАРТА ФАЙЛОВ И ПОТОК ДАННЫХ

Assets/Overtone/Scripts/
  PrototypeSettings.cs  — настройки и статическая палитра Palette.
  MediaNetwork.cs       — каналы, координаты, сообщества и построение связей.
  SpreadSimulation.cs   — расчёт распространения, вероятности, аудитории; также структуры каналов и попыток.
  GameSession.cs        — правила игры, состояния, таймер, жизни, раунды и сохранение.
  GameView.cs           — экраны, кнопки, карточки, граф, звуки и анимации.
  NewsData.cs           — структура данных новостей и enum Camp.
  CircleGraphic.cs      — рисование кругов/колец и круглая область клика; наведение ChannelPointer.
  LifeIcon.cs           — графический значок сердца.

Assets/Overtone/Resources/
  PhaseOneNews.json     — новости первой фазы.
  PhaseTwoNews.json     — начала и продолжения второй фазы.

Assets/Overtone/Editor/PrototypeBuilder.cs
  — служебное создание сцены, Canvas, шрифта и ссылок. Для обычных правок НЕ нужно снова запускать Overtone/Create prototype scene: команда перестраивает сцену.

Основная цепочка:
  GameView.Start → GameSession.Initialize
                → загрузка JSON + MediaNetwork.Create
  Действие игрока → метод GameSession → событие Changed → GameView.Render
  Публикация → SpreadSimulation → GameSession.Spread → анимация групп связей

GameSession решает, что произошло. GameView показывает результат. SpreadSimulation считает распространение. Старайся сохранять это разделение.

4. РАСПОЛОЖЕНИЕ И ДАННЫЕ КАНАЛОВ

Открой MediaNetwork.cs и найди массивы:
  positions — координаты;
  names     — названия;
  topics    — тематики;
  audiences — аудитории.

Все четыре массива должны иметь ОДИНАКОВОЕ количество элементов. Элементы с одним индексом относятся к одному каналу.

Индексы начинаются с нуля:
  positions[0], names[0], topics[0], audiences[0] — кружок №01;
  индекс 53 — кружок №54.

Например, у первого канала координаты записаны так:
  new Vector2(204.6f, 146.2f)

Первое число — X, второе — Y. X растёт вправо, Y — вниз. Это координаты внутри панели графа, а не всей сцены и не мировые Unity units.
Чтобы немного сдвинуть канал вправо, увеличь X. Для движения вверх уменьши Y. После правки проверь расстояние до соседей.

Текущая панель графа — примерно 996 × 554 условных пикселя. Верх занят легендой, низ — подсказкой и полосой просмотров. Для центров узлов ориентируйся на X около 40…955, Y около 75…400, дополнительно учитывая радиус кружка и пульсирующее кольцо. Это ориентир, а не автоматическое ограничение.

Радиус определяется MediaNetwork.Radius(audience). Сейчас:
  18 + sqrt(audience / 22000) * 8

Изменение audiences влияет сразу на просмотры, размер кружка и геометрическую проверку внутренних связей. Если нужны только другие размеры, меняй Radius, а не аудиторию.

Сообщества находятся в массиве Communities:
  name   — полное имя в подсказке;
  label  — короткая надпись на карте; \n означает перенос строки;
  center — центр подписи и фонового круга.

ВАЖНО: изменение center НЕ передвигает каналы. Чтобы сдвинуть всё сообщество на (+30, −20), прибавь эти числа ко всем шести его positions и к его center.

Членство определяется порядком, а не расстоянием и не темой:
  индекс сообщества = индекс канала / 6 (целочисленно).
  0…5 — первая группа, 6…11 — вторая, 12…17 — третья и т. д.

Лагерь и сообщество — разные вещи:
  camp: 0 — провластный, 1 — оппозиционный, 2 — нейтральный.
  cluster: номер сообщества.
Первые три сообщества целиком соответствуют трём лагерям. В остальных лагеря чередуются по формуле (group + local) % 3. Изменение topics не меняет cluster автоматически.

Платформы заданы локальным массивом platforms в Create и повторяются в каждой шестёрке. Замена его первого элемента изменит платформу первого канала КАЖДОЙ группы. Для индивидуальных платформ нужен массив на все каналы и обращение platforms[i] вместо platforms[local].

Первый канал каждого сообщества доступен для публикации:
  canPublish = local == 0
Для двух стартовых каналов в группе можно написать:
  canPublish = local == 0 || local == 3

5. КАК ДОБАВЛЯТЬ И УДАЛЯТЬ КАНАЛЫ

Самый простой путь сейчас — добавлять ЦЕЛОЕ сообщество из шести каналов в конец.

1) Добавь шестёрку координат в positions.
2) Добавь шесть названий, тематик и аудиторий в соответствующие массивы.
3) Добавь описание сообщества в конец Communities.
4) Добавь хотя бы один мост к новой группе в gateways.
5) Обнови надпись «9 сообществ» в GameView.Network.
6) Проверь размеры карты, отсутствие наложений и доступность новой группы.

При нынешних 54 узлах новая группа займёт индексы 54…59 и получит cluster = 9. Например, мост:
  {50,54}
свяжет существующий канал с индексом 50 (видимый №51) с новым №55.

Это пример формата. Выбирай реальные подходящие узлы: явные мосты не проверяются Clear автоматически.

Почему не стоит просто приписать один канал:
В Create зашита схема «по 6»: i/6, i%6, Enumerable.Range(...,6), массив platforms из шести элементов и выбор первого стартового канала. Неполная последняя группа может обратиться за пределы массива.

Чтобы поддерживать произвольное число каналов в группах, нужно переделать схему данных: хранить cluster, platform, camp и canPublish явно у каждого канала, а соседей выбирать через фильтр по cluster. Это рефакторинг, а не изменение одного числа.

Для удаления удобнее убрать последнюю шестёрку, её Communities-элемент и все gateways с удалёнными индексами. При удалении или вставке в СЕРЕДИНЕ сдвигаются индексы следующих каналов: нужно пересчитать мосты. Не должно оставаться ссылок на несуществующие узлы.

При смене числа групп текст статуса можно сделать динамическим:
  session.Network.Length + " каналов / " + MediaNetwork.Communities.Length + " сообществ"

6. КАК УСТРОЕНЫ СВЯЗИ

MediaNetwork.Create строит две разновидности связей.

Внутренние:
  кандидаты берутся только из своей шестёрки;
  сортируются по расстоянию;
  добавляются, пока links[i].Count не достигнет 4;
  Clear(a,b) исключает проход через посторонний узел.

Чтобы сделать группы реже, попробуй порог 3 вместо 4. Из-за симметричного добавления и геометрических ограничений итоговая степень не обязана точно равняться порогу.

Перемещение кружка может изменить внутренние связи: они пересчитываются при Create. Если ожидаемое ребро пропало, проверь Clear — между концами может стоять другой канал.

Между группами:
  gateways = {{0,40},{0,21}, ...}
Каждая пара — индексы двух каналов. add(a,b) добавляет связь в ОБЕ стороны. Сейчас 13 мостов, по одному между каждой соединённой парой сообществ.

Добавить мост: допиши пару, например {5,18}.
Удалить мост: убери соответствующую пару.
Не добавляй дубль существующей пары. Два разных моста между теми же сообществами расширяют проход и обычно облегчают распространение; это допустимо, если так задумано. После удаления проверь, что ни одна группа не оказалась отрезана.

Явные gateways добавляются без Clear: при выборе концов сам проверь, что линия не проходит через чужой кружок.

Для полностью ручной сети внутри Create можно заменить цикл автоматических внутренних связей вызовами:
  add(0,1);
  add(1,2);
  add(2,0);
Но тогда ответственность за связность всей карты лежит на тебе.

7. СЛОЖНОСТЬ И ВЕРОЯТНОСТИ

Сначала меняй простые настройки:
  больше viewTargets → выше требуемый охват;
  меньше crossClusterMultiplier → труднее переходы между сообществами;
  меньше мостов → больше зависимость от правильного старта;
  больше audience → больше доступных просмотров, обычно легче.

Скорость checkDuration меняет время анимации, а не вероятность успеха.

Точная формула находится в SpreadSimulation.Probability:
  0.18
  + virality * 0.34
  + plausibility * (0.30 для нейтрального канала, иначе 0.23)
  + тема: +0.22 при точном совпадении, иначе −0.05
  + лагерь: +0.20 при совпадении;
             0, если одна сторона нейтральная;
            −0.20 для противоположных ненейтральных лагерей.

Результат ограничен диапазоном 0.05…0.95. При переходе между cluster он дополнительно умножается на crossClusterMultiplier в Step. Например: 0.60 × 0.85 = 0.51.

Тематики сравниваются как строки. «#наука» и «наука» — разные темы. Новую тему не нужно регистрировать в enum, но её написание должно совпадать у новости и канала.

Канал учитывается в просмотрах один раз. Пересечение реальных подписчиков разных каналов пока не моделируется: складываются их аудитории целиком. Стартовый канал тоже сразу даёт просмотры.

Виральность и правдоподобность меняй в диапазоне 0…1. После балансировки проверяй несколько запусков: распространение случайное. Один удачный или провальный раунд не доказывает баланс.

8. КАК МЕНЯТЬ НОВОСТИ

JSON-файлы в Assets/Overtone/Resources читаются при Initialize. Сохраняй их в UTF-8, соблюдай кавычки и запятые. Не оставляй запятую после последнего элемента.

Первая фаза, элемент внутри cards:
  {
    "id": "news-001",
    "headline": "Заголовок",
    "body": "Текст новости",
    "isReal": true,
    "placeholder": false
  }

isReal определяет правильное действие: true — в папку, false — в корзину. placeholder меняет маркировку карточки, но не правильный ответ. Когда придут настоящие материалы, замени тестовый текст и выставь оба поля правильно.

Пул должен быть непустым и содержать достаточно реальных новостей для folderTarget. Сейчас карточки идут по порядку, а индекс берётся по модулю длины пула. Порядок меняется перестановкой элементов JSON; перемешивания сейчас нет.

Вторая фаза: корневой объект содержит rounds. У каждого раунда opening и options из ТРЁХ продолжений. Поля продолжения:
  text          — текст;
  kind          — отображаемое описание («абсурд», «сомнительно» и т. п.);
  topic         — тема с #;
  virality      — виральность;
  plausibility  — правдоподобность;
  camp          — лагерь 0/1/2.

kind сам по себе НЕ влияет на вероятность: формула использует численные поля, topic и camp.

Для другого числа раундов изменяй rounds и viewTargets. GameSession завершает фазу по news.rounds.Length, но в GameView остаются тексты «10» и проверка session.Round == 9 для подписи последней кнопки. Их тоже нужно обновить; последнюю проверку лучше заменить на:
  session.Round == session.news.rounds.Length - 1

Для четырёх вариантов вместо трёх одной правки JSON мало: нужны изменения ChooseOption, цикла кнопок в Network и их размеров.

9. ГДЕ МЕНЯТЬ ПРАВИЛА И ФУНКЦИИ

В GameSession.cs:
  Initialize        — загрузка данных и создание сети;
  StartRun          — полный новый запуск;
  Update            — отсчёт таймера и проигрыш по времени;
  Sort              — проверка ответа и потеря допуска;
  AfterSort         — анимация, следующая карточка, переход между фазами;
  BeginPhaseTwo     — начало второй фазы и новые допуски;
  PrepareRound      — сброс одного раунда;
  ChooseOption      — выбор продолжения;
  ChooseChannel     — проверка доступности стартового канала;
  Publish           — создание симуляции;
  Spread            — очередность групп анимации и применение результатов;
  NextRound         — жизнь за провал, следующий раунд, победа;
  Finish            — конечное состояние;
  TogglePause       — пауза;
  Save/ResumeRun    — сохранение и восстановление.

Состояния:
  Menu → Sorting → Briefing → Editing → Spreading → RoundResult
                                                  ↓ следующий раунд
  Конечные состояния: Won или Fired.

Для изменения математики распространения редактируй SpreadSimulation.Step/Probability. Для изменения последовательности показа результатов — GameSession.Spread.

Сейчас Step логически рассчитывает волну и записывает попытки, а Spread группирует их по source. Все связи одного источника имеют общий CheckProgress, после группы начинается следующий источник. Проверяется только ещё не охваченный сосед.

Не добавляй случайные проверки или начисление просмотров в GameView.Update: это создаст повторный подсчёт или зависимость результата от частоты кадров.

10. ИНТЕРФЕЙС, АНИМАЦИИ И ЗВУК

GameView.cs:
  Menu / Sorting / Briefing / Network / ResultOverlay / End — соответствующие экраны;
  Render             — полная пересборка экрана по состоянию;
  Rect / Box / Text / Button / Circle — помощники создания элементов;
  AnimateSortingError — вспышка, встряхивание и баннер ошибки;
  AnimateCardOut      — вылет карточки;
  PopNode            — увеличение узла при получении новости;
  Update             — движение импульсов и обновление цифр таймера;
  Connection / Line  — рёбра графа;
  InspectChannel     — содержимое подсказки;
  PlayTone / PlaySortingErrorSound — звуки.

Параметры Rect/Box задаются как x, y, ширина, высота от верхнего левого угла родителя. Помощник сам преобразует Y в отрицательную anchoredPosition. Не меняй знак вручную в исходных данных карты.

Базовое разрешение интерфейса — 1600 × 900. В Network сейчас:
  панель вариантов: (40,269), размер 500 × 554;
  карта: (564,269), размер 996 × 554.
Если меняешь ширину карты, проверь также легенду, подсказку, счётчик и полосу охвата: часть их размеров задана отдельными числами.

Цвета — в Palette в PrototypeSettings.cs. Для общего изменения стиля начинай с них.
Звуки синтезируются в GameView.Start, отдельных .wav нет. Для другого характера сигнала можно менять частоты и огибающую или заменить генерацию ссылкой на AudioClip.

11. СОХРАНЕНИЯ И ПРОВЕРКА ИЗМЕНЕНИЙ

Прогресс хранится в PlayerPrefs под ключом:
  Overtone.Prototype.Save.v1
Звук — под отдельным ключом Overtone.Muted.

Первая фаза сохраняет карточку, папку, допуски и остаток времени. Во второй сохраняется начало задания: выход во время распространения или результата повторяет текущий раунд. runSeed делает повтор с теми же выборами воспроизводимым; новый запуск получает другое зерно.

Не переставляй значения enum GamePhase без миграции: в сохранении фаза записана числом. Для совместимости новых полей используй version в SessionSave; сейчас версия схемы 2.

Чтобы начать проверку с чистого листа, используй кнопку нового рабочего дня. Если нужно удалить только прогресс программно:
  PlayerPrefs.DeleteKey(GameSession.SaveKey);
  PlayerPrefs.Save();
Не вызывай DeleteAll без необходимости: он удалит и другие настройки проекта.

После изменения карты проверь:
  • длины четырёх массивов равны и кратны шести;
  • Communities соответствует количеству групп;
  • gateways ссылается на существующие разные узлы;
  • каждая группа достижима из остальной сети;
  • узлы, подписи, стартовые метки и импульсы не накладываются;
  • ссылки не проходят сквозь чужие кружки;
  • верный/неверный ответ, таймаут, пауза, перезапуск работают;
  • все три длинных продолжения читаются во всех раундах;
  • конечные победа и увольнение достижимы.

Изменения кода и JSON видны в Play после компиляции/нового запуска. Отдельная Builds/Overtone.app НЕ обновляется автоматически — её нужно собрать заново.

Рабочая команда из папки overtone, если Unity CLI установлен:
  unity build . --target StandaloneOSX --output ./Builds/Overtone.app --timeout 600

Также можно использовать окно Build Profiles в Unity. Убедись, что в сборку включена OvertonePrototype.unity.

Рекомендуемый порядок освоения: Inspector-настройки → перемещение одного узла → название/тема → мост → новая шестёрка → изменение правил. После каждого шага запускай игру, чтобы понимать, какое изменение дало результат.
